description: Estimate before starting: effort, risks, what the user must provide
---

When the user types /estimate <request>, do NOT write code yet. Output:

1. My understanding of the request (two or three sentences, for alignment).
2. Split into 3-7 steps; for each: expected difficulty (low / medium / high) and whether it can be verified automatically.
3. Dependencies: what the user must provide (keys, accounts, assets, decisions); write "none" if none.
4. The 2 biggest risks, and which step would expose them fastest.
5. One recommended order to start.

Rules: no time promises, only relative size; where unsure say "unsure" instead of inventing an exact-looking number.
